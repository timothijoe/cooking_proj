# 通用项目文档整理 Prompt 设计

## 目标

提供一份可复制到任意软件或机器人项目的中文 Prompt。使用者只需填写项目路径、参考项目、
领域列表和 Git 权限，Agent 即可检查现状、提炼有效历史、建立长期文档体系并验证结果。

## 模板结构

模板由六部分组成：参数区、目标、工作原则、目标目录、执行流程、交付与验收。每个领域都
必须采用以下完整结构：

```text
docs/agent/<domain>/
├── README.md
├── charter.md
├── current.md
├── chronicles/
├── evolution/
└── decisions/
```

各部分职责和更新规则必须在 Prompt 中写明：

- `docs/agent/<domain>/` 面向 Agent 和维护者；
- `tutorials/` 面向操作者；
- `README.md` 是领域导航和推荐阅读顺序；
- `charter.md` 是长期总章程，只记录目标、边界、依赖、安全原则和完成标准，并链接纪传体；
- `current.md` 是当前总览与索引，只摘要当前能力、验证、限制和近期方向，并链接纪传体；
- `chronicles/` 是编年体，按日期记录已经发生且有证据的阶段，永久保存、只追加、不删除；
- 编年体发现旧结论错误时增加勘误或后续记录，不静默改写历史；
- `evolution/` 是纪传体，按功能或模块分别记录最新、完整的当前事实；
- 纪传体必须持续更新，允许重写，并删除已经失效或被替代的旧进展，避免多个“当前版本”；
- `decisions/` 永久保存长期架构决定；决定失效时标记 `superseded` 并链接替代决定；
- 总章程和当前索引不能复制纪传体的大段细节，三者通过链接连接。

领域列表必须参数化，不假设项目一定包含仿真、遥操作或真机。大模型、数据、SDK、构建产物
和虚拟环境默认放入可配置的本地资源目录并由 Git 忽略。

## 行为边界

Agent 必须先读项目、交接文件、现有文档和指定参考项目，再开始整理；参考材料只提炼有效
事实，不照抄旧目录、绝对路径、调试流水或相互矛盾的状态。

每条命令、路径和链接都要对照仓库验证。结论必须区分文件已迁移、静态检查、自动测试、
仿真运行、GUI 人工验收和真机验收。不能把旧项目证据冒充当前项目证据。

默认允许编辑文件；本地 commit 由参数决定；`git push`、删除用户文件、连接真机和实际运动
必须得到单独明确授权。任务结束时报告结构、关键取舍、验证、未验证项和提交信息。

## 验收标准

- 模板可以脱离本项目上下文独立使用；
- 所有项目特有信息都集中在参数区；
- 教程与 Agent 文档职责清晰；
- 编年体和纪传体更新规则不可混淆；
- 包含大文件轻量化、安全、验证和 Git 权限规则；
- 没有未解释占位符或默认执行 `git push` 的授权。
