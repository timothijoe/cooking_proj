# Tianji 控制模式与安全语义

当前真机实验使用两组 SDK 封装：`Marvin_Robot` 提供批处理配置/发送，
`Concise_Marvin_Robot` 提供较直接的单臂接口。SDK A/B 在旧设备分别对应左/右臂，但现场
必须重新核对。关节命令使用度，项目内部轨迹通常使用弧度，转换只能发生在明确适配层。

旧控制器状态记录为：0 下伺服、1 位置跟随、2 PVT、3 扭矩/阻抗、4 协作释放、100 故障。
代码不得只看状态值决定安全：还要检查错误码、反馈帧递增、七关节有限值、目标限位、跟踪
误差和规划结果。

主要路径：

- `pln-cart`：SDK MOVLA 规划后用 planned Cartesian 位置模式执行；
- `position`：逐采样 IK 后发送关节位置目标；
- `joint-impedance`：逐采样 IK 后配置关节阻抗 K/D 并发送关节目标；
- `cart-impedance`：保留的笛卡尔阻抗实验路径，尚无迁移后真机验收。

`--execute` 是发送运动目标的授权门，但不保证“不带它就完全离线”。切菜共享实现、位置调试
和点动 dry-run 仍会连接并读取反馈，部分路径还会配置控制状态。完全离线规划只使用明确标注
为 offline 的工具。

旧项目曾遇到 SDK API 名称误用、B 臂反馈为默认值、state=100、批命令未同步和模式切换失败。
因此联合控制必须一次批量暂存 A/B 目标后发送，并在运行中持续验证两臂反馈。不要依赖单次
连接成功或 `send_cmd()` 返回值推断实际运动正确。
